# Ai Bridge

将 MarginNote 中工作流指定的卡片内容及手写图片传入 DeepSeek、豆包、ChatGPT 或 Gemini 网页。默认顶部显示 **DeepSeek / 豆包 / 设置**，可在“设置 → 关于插件”启用 GPT、Gemini，至少保留一个网页。整条顶栏可拖动，右下角保留窗口缩放手柄。各网站使用独立页面，切换保留页面与草稿，首次打开时才加载。

当前正式版本为 **1.0.4**，安装包为 `Ai Bridge-v1.0.4.mnaddon`，可从 [GitHub Releases](https://github.com/642827083/AI-Bridge/releases) 下载。最低安装版本为 **MN 4.5.0**；图片及完整卡片读取使用 MN5 的官方 `AddonWebPanel`、`window.mn` 和媒体接口。使用时需要在当前沉浸式场景模板中启用 Ai Bridge，具体接口是否开放以宿主的能力清单为准。直接登录网站使用，无需 API Key，无需安装 MN Utils。

从 1.0.4 起移除内置桌宠，设置默认打开工作流库。桌宠由独立的 MN Pet 插件提供，Ai Bridge 不读取、修改或删除既有桌宠数据。

## 安装与使用

支持 Focus Switch 的“问 AI”工作流菜单。需同时安装支持“问 AI”联动的 Focus Switch 版本：Focus Switch 展示工作流名称和目标网站，选择后由 Ai Bridge 按原流程打开目标网页并上传，仍由用户检查后发送。列表读取不上传卡片、不修改工作流；卡片、学习窗口或工作流库变化时停止旧请求。联动使用带窗口及一次性请求标识的原生通知，列表仅公开名称、网站与标识，不公开提示词或卡片内容。

1. 使用 `Ai Bridge-v1.0.4.mnaddon` 安装并启用插件；如使用场景模板，在模板插件列表中启用 Ai Bridge。
2. 在 **设置 → 工作流** 新增工作流，填写名称、目标网页、卡片条目、手写来源和提示词，然后保存。
3. 在脑图中选中一张卡片，打开目标网页并登录。
4. 点击插件顶部右侧的 **三横线**，从下拉菜单中选择工作流。右侧按钮依次为 **刷新 / 工作流 / 关闭**，设置页隐藏刷新与工作流按钮。刷新只重载当前网页，检测到草稿或待发送附件时先提醒；工作流或上传处理中暂不刷新。
5. 网页菜单选择后始终向当前 AI 上传，只使用工作流的卡片范围、手写来源和提示词，不跳到工作流指定网站。外部联动执行时打开工作流指定网站。检查附件和输入框后自行点击发送，插件不会自动发送。

设置页分类为 **工作流 / 关于插件**。工作流库替代原通用上传设置，工作流按各自配置执行；历史通用设置不再显示。

只有点击上传才会读取所选内容。读取过程中会临时显示官方媒体读取面板，完成后自动收起。不会修改卡片、保存正在编辑的笔迹或切换手写层。

## 工作流

在 **设置 → 工作流** 点击“新增工作流”，设置名称、联动目标网页、卡片条目、手写来源和提示词，点击“保存工作流”。最多保存 20 个，支持编辑、复制、删除和上移、下移排序；排序即时保存，并同步用于顶栏工作流菜单。点击“复制”会将设置带入新草稿，修改后保存为副本。每个工作流独立保存，不改动通用上传设置。也可以清空卡片条目、手写选“无”，只填写提示词。

工作流库顶部的“导入／导出”支持勾选多个工作流，以 JSON 文件备份、分享或在其他设备导入。导入先预览，重名自动调整，确认后追加到现有列表末尾；取消或保存失败保留原列表。导出调用 MN 的系统保存窗口，请在窗口中完成保存。文件包含工作流设置及提示词，不包含实际卡片内容或手写图片。

工作流从 MN 文档目录中的 `AI-Bridge/workflows.json` 读取和保存，不自动迁移或清理旧目录。等待或读取期间切换卡片、网站、关闭面板或进入后台会停止执行；读取或保存失败会保留原文件和编辑草稿。

卡片图片按所选条目顺序在前，另选的手写在后；同一图片重复选中时只传一次。卡片文字保留 Markdown 和公式，已作为附件上传的 MN Markdown 图片引用不重复填入正文。

## 限制与故障处理

- 首版按单张选中卡片上传，不自动遍历子卡或整个学习集。
- 单批最多 5 张图片、合计 10 MiB；卡片文字最多 18 万字符，附加提示词最多 1 万字符。这些是插件处理上限，各网站的实际限制以网站为准。
- 卡片内容最多勾选 200 条，支持第 1 至第 10000 条的序号配置；所选卡片缺少指定条目时会提示调整设置，不会悄悄跳过。
- 脑图手写仅读取所选卡片对应的媒体项，不对整个脑图屏幕截图。没有已保存笔迹时会提示，不用其他卡片或评论手写代替。
- 若网页提示找不到附件控件，先点击当前网站自身的附件按钮，让网页建立文件控件，再重试。网站结构可能改版，适配需实际登录后的网页验证。
- 原有草稿会保留并追加文字；读取期间继续编辑草稿、切换卡片/学习集/对话、切换网站、关闭面板或切换设置都会停止待上传任务。
- 已交给网页的附件可能继续由网站处理。失败或结果不明确时先检查网页，避免重复添加。
- 网站如何处理图片、是否提供文字识别及其模型能力，由网站决定；插件只负责传递，不额外识别笔迹。
- 登录态由网站 WebView 管理。插件不提取 Cookie，也不使用其他浏览器的登录信息。

## 验证情况

自动测试覆盖卡片范围、手写读取、图片 OCR 排除、上传顺序与去重、草稿保留、跨网站任务隔离，以及工作流编辑、排序和备份。本次也覆盖顶栏工作流、刷新前草稿提醒、设置页空白恢复和图标无损压缩。

本地浏览器验证了四个网页适配的内容交付，以及多种宽度下的工作流与导航设置。网页收到附件不代表网站服务器已上传成功。

当前开发环境为 Windows，无法直接运行 iPad/macOS 的 MarginNote。**MN 内窗口、场景媒体接口、网站登录后的实际输入区与服务端附件上传仍需真机验收**，本地测试不代表这些环节已通过。

## 开发

```powershell
npm ci
npm run check
npm test
npm run build
```

默认构建只替换固定测试包，并解压逐文件比对源码和资源。正式打包使用 `npm run build:release`，版本由用户指定，拒绝覆盖同名正式包。

- `src/`：JavaScriptCore 原生窗口、设置、卡片选择及传输控制。
- `web/src/deepseek.js`：DeepSeek 网页输入和附件适配。
- `web/src/doubao.js`：豆包网页输入和附件适配，按 Tiptap 段落读取草稿，避免换行校验误报；无唯一附件控件时使用图片粘贴交付。
- `web/src/gpt.js`：ChatGPT 网页输入和附件适配。
- `web/src/gemini.js`：Gemini 的 Quill 输入区、附件组件和图片交付适配。
- `web/src/composer-bridge.js`：网站共用的草稿追加、图片交付与任务校验。
- `web/src/media-reader.js`：官方场景页面中的只读卡片与图片读取。
- `web/src/settings.*`：设置页面，通过 bridge 交由原生保存偏好。
- `assets/icon.png`：用户提供的 AI 图标原图，构建时居中缩放为透明工具栏图标。

参考本机 Jifengjincao Bridge 的浮窗和脑图手写读取流程，以及 Gemini Bridge 的窗口边界处理；未修改参考项目。
